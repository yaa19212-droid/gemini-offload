## Authority and scope

This document fixes the agent-facing MCP response-surface decisions discovered after the
0.3.0 setup/model implementation was functionally complete. It is a follow-up design
decision, not a rewrite of the original frozen plan.

Where the original frozen plan preserved response compatibility or legacy discovery
shapes, this document supersedes that choice **only for agent-facing response
serialization**. It does not change request compatibility, durable run-state formats,
credential manifest formats, quota/rotation behavior, or background-run semantics.

The target surfaces are:
- `check_gemini_setup` structured results;
- `list_gemini_models` structured results;
- `call_gemini` blocking/background receipts and item results;
- shared output/usage projection rules needed by those surfaces.

`manage_gemini_run` is out of scope except where a shared projection helper is reused.
## Core rule

The MCP response surface must expose information only when it changes an agent's
next action, diagnosis, selection, or retrieval strategy.

The following are not valid reasons to expose a field:
- it is easy to calculate from another returned field;
- it mirrors an internal object name;
- it preserves an internal compatibility alias without a real consumer;
- it duplicates the same fact using different wording.

Internal registries, runtime state, and debugging records may remain richer than
the public agent projection.

## Projection boundary

Introduce explicit agent-facing projection helpers between internal structures and
`structuredContent`.

Preferred flow:

```
internal registry/runtime result
        -> public projection
        -> MCP structuredContent
```

Do not make internal dataclasses, SDK responses, or runtime summaries become the
MCP contract accidentally.

## Compatibility policy

Do not preserve legacy response fields by default.

Compatibility preservation requires an identified external consumer or a durable
stored format. MCP structured responses in this private tool are not treated as
a database schema.

## `check_gemini_setup` response

### Decisions

- Remove `ready` from the public response.
  - Current implementation makes it equivalent to `status == verified`.
  - `status` already contains the higher-information state machine:
    `verified`, `invalid`, `unverified`.

- Keep diagnostic paths and recovery information.
  - Paths exist for filesystem-capable recovery agents.
  - Credential paths must not reveal credential contents.

- Return `next_action` only when an actual action is required.
  - Remove success-only messages such as `Gemini offload is ready.`
  - Keep actionable setup remediation guidance.

- Prefer resolved paths over opaque summaries.
  - `run_root` and `output_root` should identify actual locations.
  - Temporary/default status remains useful when it changes recovery behavior.

### Field policy

Keep:
- manifest source/path;
- manifest existence;
- Vertex location;
- credential entries with status and project identity;
- run/output root information;
- sanitized errors.

Remove or transform:
- aggregate fields duplicating array length;
- private credential identifiers;
- success messages with no action value.

## `list_gemini_models` response

### Decisions

The legacy triple projection is removed:

- `models`
- `model_characteristics`
- `model_capabilities`

These structures describe the same model identity multiple times and were kept
only as compatibility aliases during initial registry introduction.

The MCP response should expose one authoritative model collection derived from
the curated registry.

Preferred shape:

```json
{
  "models": [
    {
      "id": "gemini-3.7-flash",
      "selection_role": "default",
      "release_stage": "stable",
      "guidance": "...",
      "capabilities": {}
    }
  ]
}
```

### Public capability rules

Keep capability data when it affects:
- model selection;
- request construction;
- feature compatibility checks.

Keep:
- selection role;
- release stage;
- input/output modalities;
- thinking levels;
- thought-summary support;
- Google Search support;
- JSON schema support;
- media-resolution support.

Do not expose internal-only policy state:
- safety OFF compatibility;
- unresolved internal evidence markers.

If future location restrictions affect user-visible model choice, expose an
explicit actionable location constraint rather than a passive verification flag.

## `call_gemini` response

### Blocking runs

Blocking runs must not expose internal background-run identifiers.

Remove:
- generated `run_id` when no durable run exists;
- lifecycle fields that merely echo an internal execution choice;
- aggregate fields that duplicate a single result.

Keep a stable `results` collection shape. Do not create separate single-result
and batch-result contracts.

### Background runs

Background responses continue to expose actual control handles:
- run ID;
- run directory;
- status/event/locator paths;
- retrieval guidance.

These fields represent real future operations and are not internal leakage.

### Item result policy

Keep:
- item ID;
- success/error state;
- selected model;
- generated content or output path;
- actionable retrieval guidance.

Remove:
- array index;
- elapsed timing unless a future explicit performance feature needs it;
- SDK passthrough metadata;
- duplicate character/line counts outside file-backed retrieval cases.

## Usage normalization

Do not expose raw Google SDK usage metadata.

Normalize into an agent-facing usage object containing only useful accounting
information, for example:
- input tokens;
- output tokens;
- thinking tokens when available;
- total tokens.

Detailed SDK fields and nullable implementation metadata are not part of the MCP
contract.

## Required implementation changes

1. Add public projection helpers instead of returning internal structures.
2. Replace the model discovery triple projection with one registry-derived model list.
3. Remove meaningless success-only setup actions.
4. Normalize usage metadata before MCP exposure.
5. Separate blocking receipts from background control handles.
6. Update contract tests to assert useful information rather than legacy field
   presence.

## Non-goals

This fix does not:
- redesign Gemini request schemas;
- expose new user tuning controls;
- change model defaults or fallback ordering;
- change credential security boundaries;
- remove internal diagnostics needed for debugging;
- remove durable background-run functionality.

## Validation requirements

Before implementation completion:

- MCP tool schemas must remain compact.
- Public responses must not contain duplicate representations of the same fact.
- Tests must verify both retained information and removed accidental surface area.
- Internal registry/runtime richness may remain unchanged where it improves
  maintainability.
